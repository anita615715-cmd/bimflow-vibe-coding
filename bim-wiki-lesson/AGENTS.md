# AGENTS.md｜LLM Wiki 教學簡報生成規範

## 目的
本專案：`bim-wiki-lesson/`，將可追溯的 BIM／Revit 文件整理為 LLM Wiki，並用 Wiki 產生初學者能理解的 HTML 簡報。

## 邊界
- **禁止修改**儲存庫根目錄的第五週 BIMFlow，以及 `bim-atlas/` 第九週網站。
- 不加入登入、付費 API 或專案私有資料。
- 以繁體中文、台灣慣用詞。幫初學者理解概念，避免不必要的專業術語。
- 未經驗證的工程規格、管徑、尺寸或法規不得虛構。模擬資料一律標示。
- 不得宣稱已操作 Revit 或驗證真實圖面。

## 工作順序（不可跳過）
1. **先討論、後生成**：確定教學受眾、學習目標、至少五個資料來源及知識範圍。
2. **Ingest**：每一來源在 `raw/SXX.md` 建立摘要，並在 `data/manifest.json` 記錄 URL、版本、來源性質和限制；不可把未讀資料寫成已查閱。
3. **LLM Wiki**：建立 `wiki/WXX.md`，保留觀點、教學案例、檢查清單、對應來源編號。同步更新 `data/wiki.json`。
4. **引用檢查**：檢查每個 SXX 是否存在於 manifest、每個 WXX 是否有來源、來源版本是否合用；任一失敗要回到 raw/wiki 修正。
5. **簡報生成**：`data/slides.json` 中每張投影片必須有 `chapter`、`sourceIds`，保留一致的教學目標。
6. **簡報驗收**：執行 `node tools/validate.js`，使用瀏覽器操作 `index.html` 和 `wiki.html`，核對頁碼、來源、內容、鍵盤操作及手機版。
7. **反思**：紀錄實際失敗、是如何發現的、在哪一節點提早檢查。若採用故障注入測試，必須清楚標示為測試，不可假裝是自然故障。

## 來源與版次
- 官方文件可直接引用短篇轉述與 URL，禁止大量複製原文。
- S06 為 Autodesk Revit 2024 版官方資料；簡報不可以宣稱所有 2023 操作完全一致。
- BIM Atlas 自製案例只有教學用途，沒有真實業主／原廠核定效力。

## 修改規則
- 改動 raw：先確認來源、修訂 manifest，再重檢 wiki。
- 改動 wiki：核對來源後更新 `data/wiki.json`，再檢查有無影響投影片。
- 改動投影片：遵循 `data/slides.json` 的既有格式，不複製獨立 HTML。
- HTML 可共用視覺模板，樣式放在 `assets/site.css`。
- 修改完成後更新 `CHECK_LOG.md`，清楚記錄「已實際驗證」與「尚待現場驗證」。

## 完成定義
- >= 5 份來源筆記、每份有原始 URL 或明確可回查的來源。
- Wiki 每個章節都有來源編號。
- 教學簡報能用文字與例子幫新手理解 BIM 前置檢核，並可以回到 Wiki。
- 沒有孤兒來源、失效的內部連結或遺失的章節 ID。
- loop / graph 與反思紀錄可在儲存庫直接查閱。
